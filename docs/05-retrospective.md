## 2. 最难的问题（按难度排序）

### 2.1 "未裁决冲突"的边界拿捏
难在：什么情况算冲突、什么情况算"有隐含优先级可以按一份回答"。制度文件里"补充规定""实施细则"这类标题可能被误读为优先关系；版本日期新旧也不等于生效优先级。最终做法：把纪律写死在 system prompt（列冲突、双引用、追问、禁止按日期选边），并用 E2 真实运行 + 测试断言固化；裁决性信息（若文档明示替代关系）才允许收敛为直接作答。

### 2.2 引用保真需要一个"代码级"答案
模型自证引用不可靠（会改写、转述、拼接）。最终实现 ObservationLedger：只信本会话工具真实返回的 span；归一化刻意保留标点，让"跨句拼接"过不了 `quote ∈ span` 的子串检查；校验失败只给**一次**修复回合，二次失败直接 `grounding_failed` 不交付——宁可交不出，不交错。伪造引用的自动化测试（连续两次伪造 → grounding_failed）是这条防线的回归保障。

### 2.3 多轮消息不变量（真实踩坑）
批量运行 E5 第二轮时 DeepSeek 返回 400："assistant 的 tool_calls 必须被 tool 消息逐一响应"。根因：第一轮 submit_answer 成功后直接终止，没有为该 tool_call 写配对响应，消息序列非法。修复后把"任何轮次结束/转让前，每个 tool_call_id 必须有配对 tool 响应"写成不变量（包括成功交付与预算耗尽的分支）。这个 bug 只有真实运行能暴露，是"可运行测试 > 纸面设计"的最好注脚。

### 2.4 让离线 Mock 不沦为"假 ReAct"
考核明确：固定条件分支不算 ReAct。最终把 Mock 做成"观察特征向量 + 优先级策略"的纯函数（只看最近工具结果、本回合检索/读取计数、历史问题），不读取场景 ID、不对问句做决策等值分支；查询改写用数据层表驱动（`data/rewrite_map.json` 精确匹配，仅覆盖入表变体，不声称通用改写能力）；trace schema 与真实后端完全一致，并在三处（README / 02-solution / 04-ai-usage）声明其边界：只验证流程，不证明真实决策效果。

### 2.5 终审审计又抓出一批"只会在真实链路暴露"的问题
交付前的三路并行审计（考核合规 / 代码质量 / 文档一致性）发现了几个有价值的缺陷，均已修复并补回归测试：
- **伪造引用借道**：`not_in_corpus`/`tool_failure` 原本跳过引用校验且未强制引用为空，模型可夹带伪造引用过关 → 现在这些状态携带引用即判失败，且冲突交付强制双引用；
- **同批多 tool_calls 提前终止**：submit 成功后同批其余调用未补配对响应，多轮续跑会 400 → 统一补齐配对响应（含 NOT_EXECUTED/预算耗尽分支），新增消息不变量回归测试；
- **命中片段选句跑偏**："年假有几天"的检索片段曾选到"试用期员工不享有年假…"，"报销期限"曾选到"注意事项"小节 → 选句评分加入小节标题重叠与数字偏好，并加断言；
- **纯文本催促计数错误**：原实现累计而非"连续"，跨轮会提前误判未完成 → 改为连续计数并在工具调用成功后复位；
- **文档与事实不符**：E4 实际执行路径、测试数量口径、批量复跑命令的覆盖风险等 → 全部按实际结果重写并对齐。
结论：审计这 30 分钟非常值——它找到的都是"自动化测试没覆盖到、但评审一眼能看出来"的问题。

## 3. 学习收获

1. **评测导向的工程取舍**：本题的评分核心不是功能多少，而是"决策循环是否真的由观察驱动、边界是否诚实"。薄循环 + 强校验 + 真实 trace 比堆框架更有效。
2. **不变量思维**：tool_call_id 配对、Ledger 证据来源、步数口径——把这类"协议级不变量"显式写进代码与文档，能在批量运行中快速定位问题。
3. **诚实的 Mock 设计**：Mock 的价值在于可复现地验证流程与边界分支，必须主动声明它证明什么、不证明什么。
4. **数据驱动可验证性**：把"换语料行为改变"做成 E8 场景 + 参数化测试，比在文档里保证"我们没有硬编码"更有说服力。

## 4. 下一步（如果继续迭代）

1. **检索升级**：bigram 词法 → 混合检索（向量 + 词法），并用 E4 类口语问题构建召回评估集（命中率/改写次数指标）；
2. **语义级引用校验**：在字面校验之上加"NLI 判定引用是否支撑结论"，覆盖"引用真实但不支撑"的灰色地带；
3. **冲突知识增强**：识别制度中的适用范围/生效/替代关系字段（版本、章节、发文部门），把"未裁决"判定从纯模型判断升级为"结构化元数据 + 模型"混合；
4. **评测集扩充**：为六类验收点各构造 10+ 变体问题（不同措辞、部分命中、多轮混合），建立回归基线，量化每次 prompt/检索变动的收益；
5. **工程化**：执行记录接入结构化日志、失败样本自动归因（检索失败/引用失败/步数耗尽），并对真实模型跑多温度重复实验评估稳定性。
