# 04-ai-usage.md — AI 辅助说明（如实记录）

## 1. 使用的 AI 工具

| 工具 | 用途 |
|---|---|
| Claude Code（CLI 编码智能体，Anthropic） | 设计草案撰写、代码实现、测试编写、文档起草、运行与验证流水线 |
| 并行子代理（同环境，多个只读评审代理） | 开发前的**多视角设计评审**（考核规范合规 / 工程可行性两路独立评审）与交付前的最终审计 |

## 2. AI 承担的辅助内容

- `docs/02-solution.md` 设计草案（经评审修订 v2）；
- `src/` 全部代码（corpus / tools / grounding / llm / agent / cli）的初稿与修正；
- `data/` 合成文档集与 `data/rewrite_map.json` 的初始文本（口径由设计文档约束）；
- `tests/` 测试用例初稿；
- `examples/` 的运行脚本调用与结果整理；
- `docs/01、03、05` 与 README 的起草。

## 3. 本人（候选人）的贡献与决策

- **选题决策**：四题对比后选择题3（企业知识问答 Agent），确认技术栈（Python + DeepSeek + 原生实现）与仓库/账号配置；
- **验收标准确认**：逐条确认题面"必须验收"六项与全局规则（步数上限、双执行路径、Mock 边界、替换语料）作为验收门槛；
- **关键取舍裁决**：
  - 冲突纪律：未裁决冲突必须双引用 + 追问，不得以日期新旧选边；
  - 引用保真校验：用代码级 ObservationLedger 强制校验，不信任模型自证，二次失败降级 `grounding_failed`；
  - 步数口径：1 步 = 1 次工具调用（含 submit_answer），预算耗尽立即返回 `step_limit`；
  - 状态枚举：模型可选 4 值，循环层追加 `step_limit`/`grounding_failed`；
  - Mock 诚实边界：Mock 只证明流程，不证明真实模型决策；
- **过程控制**：要求"设计评审通过后再进入实现"、"全部场景用真实模型跑通再交付"，并对评审意见逐条裁决采纳；
- **最终验收**：确认真实运行 trace 的状态、引用与行为符合预期后才提交。

## 4. 验证结果（AI 产出不是"看起来对"，而是被测过）

- `pytest -q`：**52 passed, 2 deselected**（离线确定性，默认不跑真实模型用例）；`pytest -q -m real_model`：**2 passed**（DeepSeek 冒烟）。记录见 `examples/test-results.txt`；
- 8 个场景全部用真实 DeepSeek 运行并落盘 trace/答案（`examples/`），结果与预期逐一对照见 `docs/03-evaluation.md`；
- 开发过程中真实暴露并修复的缺陷示例：批量运行 E5 时第二轮请求被 API 以 400 拒绝（成功交付 submit_answer 后未补 tool 响应，违反 `tool_call_id` 配对不变量）——修复后新增回归测试并全量复跑通过；
- 交付前的多代理终审又发现并修复：无引用状态可携带伪造引用绕过校验、同批多 tool_calls 提前终止未补配对、命中片段选句与问题无关、批量复跑可能用 Mock 覆盖真实 trace 的文档误导、测试计数口径不一致、E4 实际路径与文档描述不符等问题（修复明细见 git 提交记录与 05-retrospective §2.5）。
