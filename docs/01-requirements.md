# 01-requirements.md — 需求文档

## 1. 用户与场景

| 项 | 内容 |
|---|---|
| 用户 | 企业员工（提问者），需要查制度/FAQ 类问题的可靠答案 |
| 场景 | 报销、年假、考勤、发票等制度问题；问题可能是口语化、追问式，或制度中根本没有答案 |
| 用户痛点 | ① 制度文件多且分散，不知道哪份适用；② 不同文件说法冲突时无法判断以哪份为准；③ 担心被"看起来合理"的编造答案误导 |
| 系统角色 | 企业知识问答 Agent：检索 → 读取 → 查证 → 依据原文作答或明确说明缺口/冲突 |

## 2. 输入与输出

**输入**
- 问题文本，及可选的多轮对话历史（追问场景）；
- 合成制度文档库 `data/docs/`（每篇带 `doc_id`、`version_date`、分节正文）。

**输出（结构化交付，submit_answer）**

| 字段 | 含义 |
|---|---|
| `status` | `answered` / `needs_user_confirmation` / `not_in_corpus` / `tool_failure`（另有两个循环层状态 `step_limit` / `grounding_failed`） |
| `answer_text` | 面向员工的回答或说明 |
| `citations[]` | 引用：`doc_id` + `version_date` + **逐字原文片段** |
| `gaps` | 资料缺口（资料外问题时必填） |
| `followup_question` | 需要用户确认时的追问 |
| `incomplete_reason` | 未能完成时的原因 |

## 3. 范围

**做什么**
- 检索/读取/列清单三个只读制度的本地工具 + 故障注入演示；
- 模型驱动的 ReAct 循环（决策完全由模型给出，步数上限 8，可配置）；
- 代码级引用保真校验（引用必须来自本会话真实工具观察）；
- 冲突处理纪律（未裁决冲突必须列双方引用并追问，不得擅自选边）；
- 多轮上下文追问；离线 Mock 入口（无密钥可运行）。

**不做什么**
- 不做真实发布/写操作（本题目为问答 Agent，全只读）；
- 不做向量检索/重排（当前规模下词法检索 + 模型改写已足够，见 02-solution 取舍）；
- 不做 Web 界面、线上部署、多 Agent 编排（考核明确非必需）。

## 4. 成功标准（对应题面"必须验收"与全局规则）

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | 明确答案：回答有依据、引用逐字可核 | E1 运行记录 + 引用保真校验 + 测试 |
| 2 | 文档冲突：列出冲突双方与引用、请求确认、不擅自选边 | E2 运行记录（D01/D02）+ 测试断言 |
| 3 | 资料外问题：明确缺口、不编造 | E3 运行记录 + 测试断言 |
| 4 | 改写后的相似问题：口语问题经查询改写后能找到制度依据并作答 | E4 运行记录（模型将口语问法改写为制度用语检索并命中 D06）；离线测试另覆盖"首查 miss→改写→命中"机制 |
| 5 | 上下文追问：结合历史解指代后作答 | E5 两轮运行记录 + 测试断言 |
| 6 | 工具失败：如实处理失败（重试/降级/明确失败） | E6 故障注入运行记录 + 测试 |
| G1 | 至少两条体现"模型根据工具结果调整动作"的执行路径 | E2（冲突路径）与 E6（故障路径）对照，另有 E3/E4 补充路径（见 03-evaluation §2） |
| G2 | 步数/工具调用上限，触达返回明确未完成状态 | E7（max_steps=1）+ 单元测试 |
| G3 | 至少 3 组输入覆盖全部验收点 | E1–E8 共 8 组（examples/） |
| G4 | 替换文档内容，答案与动作随之改变 | E8 换语料运行记录 + 参数化测试 |
| G5 | 离线可运行并声明 Mock 边界 | `--backend mock` + README/04-ai-usage 声明 |
